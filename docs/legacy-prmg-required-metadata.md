# Legacy PRMG required metadata — draft rollout contract

This change fixes the legacy service as a separate compatibility path; it does not activate the shared HLOA service or deploy either repository. An actual pre-fix legacy HTTP-route rehearsal returned a live quote from synthetic missing-lock/missing-term rows using strict modeled database reads. That reproduction is not SQL persistence evidence; the new opt-in PostgreSQL CI cases exercise the actual refresh, migrations, repositories and HTTP router in an owned throwaway database.

The legacy normalizer now requires explicit consistent integer lock metadata and explicit term units, using the corrected HLOA validation behavior. `term_months` means months, `term_years` means years; generic `term` requires integer month/mo/year/yr units. A product label such as `30 Yr Fixed`, `30-Year Fixed` or `(30 Yr Fixed)` also supplies units. Every term-bearing product fragment is checked: a malformed decimal/negative/unknown fragment cannot hide behind a valid term or explicit months. Missing, fractional, conflicting, malformed or unitless values are excluded with sheet/row reasons. Existing database integer bounds are not lender eligibility thresholds.

Any otherwise-priceable row rejected for required metadata fails the entire publication, preserving prior snapshots and existing row-count drift checks. Matrix lock headers are not rounded. Missing matrix price/rate cells stay missing; a blank price cannot become a genuine zero. Explicit zero and negative credit are preserved. Product/channel/price-sign conventions are otherwise unchanged and still require an authorized vendor specification before live use.

New publications use `prmg-normalizer-v3` (distinct from the shared HLOA `-hloa` marker). Successful validation records the marker in existing JSONB. Quotes refuse old/unmarked/malformed snapshots before loading their rows and reread current publication identity/provenance after asynchronous row loading. Refusal uses the existing `no_live_pricing` contract with empty options. No cached response server exists in this legacy service; already delivered browser results cannot be remotely revoked by this patch.

Compatibility is intentionally fail closed: every pre-v3 snapshot stays stored but is unavailable to the corrected quote path until a real v3 refresh validates the source. The transform hash reprocesses identical bytes once. Never relabel old normalized rows, autoapprove a policy, lower drift thresholds, or describe retained status=live/health200 as proven quote availability. No DB migration or existing policy edit is required. A failed refresh preserves a prior validated v3 snapshot; preserving a v2 snapshot does not make it servable.

This is internal data-integrity provenance, not lender authentication, approval, price-validity duration or a lease. Legacy pricing still lacks the shared HLOA policy-authority/temporal validity enforcement. This patch makes no claim of production readiness, source rights, qualification, current lender pricing, automatic LendingPad transfer or receiver acknowledgment. Production release, source/units verification and configuration remain separate gates; no live calls or deployment are part of this work.

Tests use only synthetic inputs. Local service tests do not connect to a database. Real PostgreSQL tests require explicit `LEGACY_PRICING_TEST_DATABASE_URL`, test mode and loopback host, create a random `cmr_legacy_metadata_…` database, apply existing migrations only there, and close/drop only that owned database. Workbook downloads are stubbed to a loopback-only synthetic URL, scheduling/startup work is disabled and HTTP listeners bind 127.0.0.1. Normal locked dependencies are installed under pricing-engine with lifecycle scripts disabled; no global packages or credentials are added.
