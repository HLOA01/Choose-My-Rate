# TEST built-artifact application preview

Run `CMR_EXPECTED_SHA=<exact clean checkout commit> npm run qa:built-preview` (PowerShell: set `$env:CMR_EXPECTED_SHA` first). It requires an exact source commit, the existing repository identity and no dirty tracked or untracked runtime/config shadow inputs. This is an offline QA command, not a deployment/configuration utility.

The coordinator exports active tracked runtime inputs with git archive to a fresh Temp directory, excludes all .env files, and builds with Vite envDir:false and an allowlisted child environment. Existing tracked deployment environment values are neither copied nor used. Installed dependencies are reused through a dependency-directory link; the lockfile is hashed, but dependency bytes are explicitly NOT attested. No dependency install occurs.

Three artifacts are built: primary URL with conflicting alias (primary expected), alias only, and unset. Only explicit synthetic 127.0.0.1 URLs are accepted in TEST manifests. This reports existing precedence rather than changing production alias compatibility. Each manifest records source commit/archive hash, source-file hashes, lockfile hash, selected key, effective configuration/fingerprint and all built file hashes. Source/config/artifact drift, extra files and nonlocal inputs fail closed before serving.

The actual built output is served by Vite preview on 127.0.0.1:5196, with environment loading disabled; a synthetic receiving website uses port5197. The preview-process application URL is intentionally different from the baked URL. Existing cross-origin tests prove the baked primary/alias is navigated unchanged, including query, GET/body/referrer, storage failure, login redirect, unavailable response, return/reload invalidation, local-copy/receipt disclosure and Spanish/mobile flow. The unset artifact remains unconfigured despite the preview-process URL. Browser tests also fetch and hash every served artifact; they do not use vite dev.

All pricing/platform data is mocked. The actual-handler HLOA rehearsal remains a separate check; this report does not claim real backend integration. No provider endpoint is contacted. Positive LendingPad route recognition remains covered by the existing pure contract tests; built-preview tests cover generic synthetic destinations and must not put a real provider URL into a test artifact merely for a label. No product code, runtime destination, receiver API, receipt, application.started, approval, lender access or production readiness is added.

Reports are written under test-results/built-preview and include per-case manifest/results, runtime-override checks and both listener teardown results. A failure cannot produce passed:true. Temp snapshots are retained for inspection; no original checkout/output is erased. Ports are refused if already occupied; this command never kills a preexisting listener. Playwright owns its two TEST server processes. Browser fetch/route and WebSocket guards are not an OS-wide network sandbox and installed dependencies are not byte-attested.

CI runs this as an explicit step and uploads the synthetic report. Standard PR CI may execute a synthetic merge commit: the report records that actual checkout SHA, not an invented feature-head identity. Compare checkout/head trees before attributing the same source result to a feature head. Existing production release/configuration approval gates remain unchanged.
